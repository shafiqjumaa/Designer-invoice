# DesignerFlow — إدارة أعمال المصمم

[فتح الموقع](https://shafiqjumaa.github.io/Designer-invoice/) · [المستودع](https://github.com/shafiqjumaa/Designer-invoice)

تطبيق ويب عربي (RTL) لإدارة العملاء، أعمال التصميم، العقود، الفواتير، المصاريف، الأهداف والاشتراكات. يعمل كـ PWA عبر GitHub Pages، ويستخدم Firebase Authentication وFirestore لحفظ حسابات المستخدمين والمزامنة.

## إصدارات المشروع

- `main`: النسخة المنشورة حالياً.
- `development/cloud-safety-v1`: تطوير الأمان والمزامنة ونموذج العملاء (قيد التحقق قبل النشر).
- `npm test`: اختبارات سلامة أساسية بدون حزم خارجية، باستخدام Node 22.

## ما تحسن في فرع التطوير؟

- النسخة المحلية أصبحت معزولة حسب Firebase UID، ولا يتم نسخ بيانات حساب محلي إلى حساب جديد تلقائياً.
- تُرسل فقط **الأقسام التي تغيّرت** إلى Firestore، لا كل الأقسام في كل عملية حفظ.
- تجاهل صدى الكتابات المحلية في مستمعي Firestore، مع إظهار حالة الخطأ عندما تفشل كتابة أو قراءة السحابة.
- إنشاء الحسابات إجراء صريح، مع إمكانية استعادة كلمة المرور بالبريد.
- رابط استبيان العملاء يحمل رقم واتساب المقصود؛ العميل يجب أن يضغط زر الإرسال في واتساب، بدلاً من إظهار تأكيد استلام غير صحيح.
- تصحيح عبارة النسخ الاحتياطي: التصدير اليدوي ليس نسخة تلقائية، ومزامنة البيانات ليست بديلاً عن النسخ الاحتياطية.

## إعداد Firebase (ضروري)

1. افتح [Firebase Console](https://console.firebase.google.com/) واختر المشروع المرتبط بالموقع.
2. فعّل **Authentication → Sign-in method → Email/Password**.
3. أنشئ Firestore Database إن لم تكن مفعلة.
4. في **Firestore Database → Rules**، راجع القواعد بملف [firestore.rules](firestore.rules)، ثم انشرها في Firebase Console. **وجود الملف في GitHub لا ينشر القواعد تلقائياً**.
5. تأكد من وجود بيانات مشروع Firebase الصحيحة داخل `index.html`، ومن إضافة نطاق GitHub Pages إلى **Authorized domains** إن لزم.
6. سجّل الدخول بالحساب نفسه على الكمبيوتر والجوال، ثم جرّب تعديلاً وتحقق من ظهوره على الجهازين.

بيانات `firebaseConfig` الخاصة بتطبيق الويب ليست كلمة مرور أو صلاحية وصول، ولا تُغني أبداً عن قواعد حماية Firestore.

## نسخة احتياطية واستعادة

من الإعدادات يمكنك تصدير JSON يدوياً أو استيراد ملف. احفظ النسخة في مساحة **خاصة** خارج المستودع العام. الاستيراد يستبدل البيانات الحالية، لذلك اختبره أولاً في حساب تجريبي.

النسخ القديمة في `localStorage` تحت `designerAppDB_v3` **لا تُستورد تلقائياً** إلى حساب جديد، منعاً لاختلاط بيانات مستخدمين مختلفين. استخدم نسخة JSON التي سبق أن صدّرتها واستوردها من الحساب الصحيح.

## نموذج طلبات العملاء

في إعدادات الموقع، أدخل رقم واتساب بصيغته الدولية، ثم انسخ رابط الاستبيان وأرسله للعميل. بعد تعبئة النموذج يفتح واتساب برسالة مجهزة، وعلى العميل الضغط على **إرسال**؛ الطلب لا يُرسل مباشرة إلى Firestore.

## التطوير والاختبارات

النسخة الحالية بدون build step، وتُخدم من `index.html`. اختبارات البداية:

```bash
npm test
```

راجع [قائمة فحص الإصدار](docs/RELEASE-CHECKLIST.md) قبل دمج فرع التطوير. المرحلة التالية هي فصل الصفحات والخدمات في وحدات مستقلة وترحيل Firestore إلى مستند لكل سجل، لأن تخزين كل فئة في مستند واحد لا يسمح بتعديل متزامن آمن لنفس الفئة.

## الخصوصية

لا تضع ملفات نسخ احتياطية أو بيانات عملاء في GitHub العام. يوجد ملف `.gitignore` يمنع أغلب أنماط النسخ الاحتياطية المحلية من الإضافة غير المقصودة، لكنه لا يمنع رفع البيانات يدوياً. تنظيف سجل Git التاريخي عملية منفصلة عن حذف الملف من النسخة الحالية.
